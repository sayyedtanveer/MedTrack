# MedTrack reporting modernization — Phase 1 audit

17 November 2026 · Read-only review and implementation proposal

## Decision

Retain the existing Reports hub, finance calculations, operational queries and Phase B/C BOM rollup. Add the first analytical view for BOM cost using the existing BOM detail, tree and cost endpoints. Correct source contracts and access controls before promoting reports into the hub. Defer realized margin, actual production cost and historical inventory valuation until transaction-level cost coverage can be demonstrated.

## Existing architecture and access

- Reports navigation lives in frontend/src/lib/constants.ts and frontend/src/lib/roles.config.ts. The existing /reports landing is registered by frontend/src/modules/finance/routes.tsx and rendered by finance/pages/ReportsPage.tsx. It loads a fixed set of reports via frontend/src/services/finance.service.ts and renders generic object/array tables. It provides category selection, report selection, refresh, and loading/error/empty states. It lacks sortable report columns, server paging, record links, structured filters or exports. Its en-IN formatting rounds numbers over 999 and renders decimal strings separately. Currency, UOM and timestamp labels are inconsistent.
- The protected /reports/manufacturing-kpis route lives in modules/reports/routes.tsx and is linked from production. ManufacturingKPIsPage.tsx uses date controls and KPI cards. Its product/work-center inputs send parameters the endpoint does not accept. Its percentage field names differ from the response. Links for cycle time, QC, output and variance point to paths with no matching frontend report route.
- Role home dashboards use frontend/src/services/reports.service.ts, backend/app/interfaces/api/v1/routes/dashboards.py, role dashboard pages and their domain services. Separate procurement, inventory, finance, sales, manufacturing, QC, delivery, worker and planner pages already expose operational KPIs. Reuse their queries or source record links. Role-scoped portal dashboards must remain distinct from internal reports. The /reports/dashboard endpoints are a separate set of overlapping summaries.
- Both /reports and /analytics are registered in backend/app/interfaces/api/v1/router.py. Reports use a mix of ReportingService role maps, endpoint-only role checks and authentication-only endpoints. Finance's parallel /finance routes use explicit business permissions. JWT tenant scoping is pervasive on the primary records, but some joins lack tenant and soft-delete predicates. Several KPI/detail endpoints do not declare report/module permission dependencies. Align server-side access and frontend visibility with existing domain permissions, including export. Test allowed and denied roles on each route. Frontend role visibility alone cannot authorize an export.
- ReportingService lives in backend/app/application/finance/reporting_service.py. It delegates finance to FinanceService, has inline SQL for legacy aggregates, and overlaps KPIQueryService in backend/app/services/kpi_query_service.py. Some individual reports query directly in backend/app/interfaces/api/v1/routes/reports.py. Reuse or repair the owner of each calculation instead of cloning it.
- Shared TanStack DataTable has sorting, pagination and visibility state. Its default paging is client-side. Use real server filters/pagination for large reports with stable sorting and an explicit total. Recharts is already installed. Reuse theme tokens and existing page, status, currency and tenant profile patterns. Normalize report date ranges to the tenant timezone, convert date boundaries deliberately, and distinguish generated time from the underlying transaction time. Local PostgreSQL timezone Asia/Calcutta is an environment observation, not a cross-tenant contract.

## BOM analytical rules

Use the version selected by the user and show active/draft status, current calculation time, output UOM and cost readiness. The current cost basis is one output unit of the target. A parent component subtotal already includes a nested child's full cost. The top-level outside-processing and operations subtotals are for the selected BOM itself. A child may still display its own charges as explanatory detail.

For a complete tree only, a flattened view can sum extended Standard Cost leaf nodes for direct material, then add each BOM node's own scaled making and operation amounts exactly once. Exclude child composite contributions from that flattened sum. Include the root's own operation and making amounts. Detect unexpanded/truncated, invalid or incomplete branches and suppress composition percentages when the required totals or denominator are unavailable. The current tree carries display numbers as floats and operation/making summaries; use exact Decimal values from the same service before producing authoritative reconciliation. For individual operation drill-down, reuse the existing BOM operation relation and operation cost provider. Do not invent actual outside processing details from the estimated per-piece charge.

For the brief's example, the parent rolls up 2 × 180 + 40 = 400. The flattened view is 340 raw + 60 outside processing = 400. For the MedTrack case previously checked, 1200 child contribution + 12 raw + 40 parent making = 1252. Keep stored approved material Standard Cost and calculated live child BOM cost separate, including their variance and cost basis. A selectable prior BOM version shows its structure and current cost under current inputs. Existing material revision history alone does not reconstruct historical BOM cost snapshots, operation rates or version-specific historical composition.

## Export assessment and gates

- Inventory summary PDF in routes/reports.py generates HTML using existing PDF/storage support. It saves a generated file; the endpoint was not invoked. It depends on the broken stock query. Invoice and payment PDF paths in FinanceService provide existing document-rendering patterns. Resolve and verify the WeasyPrint runtime in deployment before promising report PDF. The generic ReportExporter PDF renderer expects ReportLab, which is unavailable in this environment.
- backend/app/infrastructure/services/export_service.py contains generic CSV, JSON and openpyxl XLSX rendering. No connected enterprise report workbook export was found. Reuse the existing library and streaming/file patterns. A shared serializer must emit text cells for user-entered formula-like strings, typed Decimal/date-compatible data, explicit tenant/currency/UOM metadata and the same authorized filtered result as the web view. Use Summary, Details, Cost Breakdown and Exceptions only where applicable. Add filters, frozen headings, precision policy, row-limit handling and a clear indication if a request is too large. Compare row counts and control totals across UI/XLSX/PDF.
- PDF follows the same query and filters, with paginated headers/tables, generated timestamp, page numbers and warnings. Use charts only where they remain legible. An approved screen can ship before optional PDF if the runtime still blocks validation.

## Proposed sequence for approval

1. **Contract and access corrections.** Fix Stock Summary, Sales Fulfillment and Manufacturing KPI DTO/filter mismatches in their owning services. Expose empty vs unavailable data. Align role permissions, secondary joins, date boundaries and currency units. Validate against read-only PostgreSQL plus controlled multi-tenant fixtures. Shape and eligibility checks first, then report design.
2. **Existing Reports hub and BOM Cost Analysis.** Reuse /reports, shared theme/cards/table, existing BOM APIs and expandable tree. Provide searchable report categories with descriptions and responsive layout. Use existing BOM product/version filters and drill-through. Add a compact KPI summary, reconciled breakdown, each cost's data basis and explicit exceptions. Offer version comparison as current recalculation only. Provide compare/aggregate views only where the backend guarantees a meaningful grain. Recently viewed and favorites depend on a separate persistence decision.
3. **Operational report expansion.** Inventory balances and movements, then procurement price evidence and subcontract quantities, then manufacturing output/consumption and sales/invoice analysis. Connect existing detail pages, avoid repeating domain dashboards, and test status/UOM/currency/date contracts at each milestone. Release estimated margin only after matching basis and transaction grain.
4. **Excel for approved reports.** Extend the existing exporter against each canonical query. Test precision, workbook typing, formula-safe strings, permissions, limits and reconciliation.
5. **PDF for approved reports.** Reuse WeasyPrint with validated runtime and templates. Benchmark output against the web and XLSX control totals. Gate automated schedules and actual-cost reporting on separate evidence and approval.

Acceptance for the first release includes stable totals across expand/collapse, incomplete/cycle/UOM handling, exact category reconciliation, tenant/role boundaries, pagination, desktop/mobile loading/error/empty states, and links that open authorized source records.

Product benchmarks for the proposal are source-record traceability, filter-aware analysis, and clear stock/transaction grain.
